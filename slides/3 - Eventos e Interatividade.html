01

O que são eventos

A peça que faltava para o site reagir
Parte 1 · Slide 1

O modelo escutar-e-reagir

Um evento é algo que acontece na página: um clique, uma tecla pressionada, um mouse passando por cima.

O JavaScript fica “escutando” esses acontecimentos e executa uma função quando eles acontecem. É assim que um site deixa de ser estático e passa a reagir ao usuário.
Parte 1 · Slide 2

Eventos no dia a dia da web

click

clicar num botão ou link

mouseover / mouseout

passar o mouse em cima / tirar

keydown

pressionar uma tecla

submit

enviar um formulário

change

mudar o valor de um campo

scroll

rolar a página

Parte 1 · Slide 3

Conectando com o que já vimos

Na Aula 2, aprendemos a selecionar e alterar elementos.

Hoje aprendemos quando essas alterações devem acontecer.

Seleção + Eventos = a base de praticamente toda interação que existe num site.

02

addEventListener

Ensinando o JS a escutar a página
Parte 2 · Slide 4

Sintaxe básica

Todo listener precisa de três coisas: o elemento, o tipo de evento e uma função a executar.

const botao = document.querySelector("#meu-botao");

botao.addEventListener("click", () => {
  console.log("O botão foi clicado!");
});
Parte 2 · Slide 5

Eventos de mouse

const card = document.querySelector(".card");

card.addEventListener("mouseover", () => {
  card.classList.add("card-destacado");
});

card.addEventListener("mouseout", () => {
  card.classList.remove("card-destacado");
});

Muito usado para efeitos visuais de “hover” que dependem de lógica, além do que o CSS :hover já resolve sozinho.

Parte 2 · Slide 6

Eventos de teclado e formulário

Tecla pressionada:

campo.addEventListener("keydown", () => {
  console.log("Tecla pressionada!");
});

Valor de um campo mudou:

select.addEventListener("change", () => {
  console.log("Nova opção escolhida!");
});
Parte 2 · Slide 7

O evento submit

Disparado quando um formulário é enviado — seja pelo botão, seja pelo Enter.

<form id="form-contato">
  <input type="text" placeholder="Seu nome">
  <button type="submit">Enviar</button>
</form>
const form = document.querySelector("#form-contato");

form.addEventListener("submit", () => {
  console.log("Formulário enviado!");
});
Parte 2 · Slide 8

Função nomeada vs. inline

Função inline (rápida, direto ali):

botao.addEventListener("click", () => {
  console.log("Clique!");
});

Função nomeada (reutilizável):

function aoClicar() {
  console.log("Clique!");
}

botao.addEventListener("click", aoClicar);
03

O objeto event

Toda informação sobre o que aconteceu
Parte 3 · Slide 9

O parâmetro event

Toda função de evento recebe automaticamente um objeto com detalhes do que aconteceu.

botao.addEventListener("click", (event) => {
  console.log(event);
});

Você pode nomear esse parâmetro como quiser, mas event ou e é a convenção mais usada.

Parte 3 · Slide 10

event.target

Diz exatamente qual elemento disparou o evento.

lista.addEventListener("click", (event) => {
  console.log(event.target); // o item exato que foi clicado
  event.target.classList.toggle("marcado");
});
Parte 3 · Slide 11

target vs. currentTarget

event.target

O elemento que realmente recebeu a ação (ex: o <li> clicado)

event.currentTarget

O elemento onde o listener foi colocado (ex: a <ul> inteira)

Essa diferença fica essencial quando falamos de delegação de eventos, mais adiante nesta aula.

Parte 3 · Slide 12

event.preventDefault()

Alguns elementos têm um comportamento padrão do navegador — às vezes queremos impedi-lo.

form.addEventListener("submit", (event) => {
  event.preventDefault(); // impede o recarregamento da página
  console.log("Formulário processado via JS!");
});

Também funciona em links (<a>) para impedir a navegação padrão.

04

Teclado e formulários

Atalhos e validação em tempo real
Parte 4 · Slide 13

event.key

Dentro de um evento de teclado, event.key diz qual tecla foi pressionada.

document.addEventListener("keydown", (event) => {
  console.log(event.key); // "Enter", "a", "ArrowUp", etc.
});
Parte 4 · Slide 14

Criando um atalho de teclado

Combinando event.key com um if, dá pra criar atalhos:

document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    menu.classList.remove("aberto");
  }
});

Muito usado para fechar modais, menus e caixas de busca com a tecla Esc.

Parte 4 · Slide 15

input, change e submit

input

dispara a cada tecla digitada no campo

change

dispara quando o campo perde o foco com um novo valor

submit

dispara ao enviar o formulário inteiro

Parte 4 · Slide 16

Uma prévia da validação em tempo real

Combinando input com condicionais, já dá pra dar feedback instantâneo:

campoEmail.addEventListener("input", () => {
  if (campoEmail.value.includes("@")) {
    campoEmail.classList.remove("erro");
  } else {
    campoEmail.classList.add("erro");
  }
});

Vamos aprofundar validação de formulários com calma na Aula 6.

05

Delegação de eventos

Um listener pode fazer o trabalho de vários
Parte 5 · Slide 17

O problema de muitos listeners

Colocar um listener em cada item de uma lista funciona, mas fica caro e complicado — ainda mais se itens forem criados depois.

// funciona, mas nada elegante
itens.forEach(item => {
  item.addEventListener("click", () => { ... });
});
Parte 5 · Slide 18

Delegando para o elemento pai

Como eventos “sobem” pela árvore do DOM, um único listener no pai já escuta os cliques dos filhos.

const lista = document.querySelector("#lista");

lista.addEventListener("click", (event) => {
  if (event.target.tagName === "LI") {
    event.target.classList.toggle("concluido");
  }
});

Isso funciona até para itens criados depois, sem precisar adicionar um novo listener a cada um.

Parte 5 · Slide 19

removeEventListener

Quando um listener não for mais necessário, ele pode ser removido.

function aoClicar() {
  console.log("Só executa uma vez!");
  botao.removeEventListener("click", aoClicar);
}

botao.addEventListener("click", aoClicar);

Só funciona com funções nomeadas — funções inline não podem ser removidas depois.

Atividade desafiadora

Menu e galeria interativos
Parte 6 · Desafio

Menu e galeria interativos

Construa uma página com um menu de navegação e uma galeria de imagens, ambos totalmente controlados por eventos.

O desafio: usar diferentes tipos de evento — clique, mouse e teclado — para criar uma experiência que realmente responde ao visitante.
Parte 6 · Desafio

O que o site precisa fazer

  • Um botão de menu (☰) que abre e fecha uma lista de links ao clicar
  • Uma galeria de pelo menos 4 imagens/cards que reagem ao mouseover/mouseout (destaque visual)
  • Um atalho de teclado: pressionar Esc fecha o menu, se estiver aberto
  • Usar event.target em pelo menos uma interação (ex: destacar a imagem clicada na galeria)

Bônus opcional: usar delegação de eventos para controlar toda a galeria com um único listener no elemento pai.

Parte 6 · Desafio

Esqueleto para começar

const botaoMenu = document.querySelector("#botao-menu");
const menu = document.querySelector("#menu");

botaoMenu.addEventListener("click", () => {
  menu.classList.toggle("aberto");
});

document.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    menu.classList.remove("aberto");
  }
});

const galeria = document.querySelector("#galeria");

galeria.addEventListener("click", (event) => {
  if (event.target.tagName === "IMG") {
    event.target.classList.toggle("selecionada");
  }
});
